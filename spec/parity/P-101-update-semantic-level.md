# P-101 · 更新语义判定 UpdateLevel

- 来源: B main@`45a7681`（见 `PARITY-BASELINE.md`），观察日期 2026-11-26
- 独立实现声明: 本实现未参照 B 源码 / 注释 / 命名，仅依据下列行为条目
- 落位: `core/domain/src/main/kotlin/com/gy/githubclient/core/domain/update/UpdateLevel.kt`

## 外部可观察行为

1. 远端与本地的**主/次版本号**（x.y）发生变化 → 判定为**强制更新**，界面不提供「跳过」。
2. 仅**修订号**（z）变化 → 判定为**可选更新**，可跳过。
3. 版本号相同但**安装包指纹**（SHA-256）与已安装记录不同 → 判定为**可选更新**（同版本重打包，可重新下载）。
4. 版本号**无法解析** → 判定为「无法比较」，**完全静默**，绝不兜底成 0.0.0，也绝不弹窗。
5. 「跳过此版」按**指纹**记录而非版本号；同一指纹不再提醒。
6. 点击安装后 **30 分钟**内不再重复提醒（安装 TTL，防装失败死循环）。
7. 本地已是最新 → **完全静默**（不弹窗、不横幅、不通知）。

## 验收用例

| # | Given | When | Then | 类型 |
|---|---|---|---|---|
| 1 | 本地 0.17.0 (20) | 远端 0.19.0 (21) | 判定强制更新，跳过按钮不出现 | 主路径 |
| 2 | 本地 0.19.0 (21) | 远端 0.19.1 (22) | 判定可选更新，可跳过 | 主路径 |
| 3 | 本地 0.19.0 (21)，指纹 A | 远端 0.19.0，指纹 B | 判定可选更新（**不强制**） | 主路径 |
| 4 | 本地 0.19.0 | 远端版本字段为 `"abc"` | 判定「无法比较」，无任何 UI | **边界** |
| 5 | 本地 0.19.0，指纹 A | 远端 0.19.1，指纹 A，且 A 在跳过集合中 | 判定静默 | 边界 |
| 6 | 任意状态 | 版本号不可解析 | 不抛异常、不兜底 0.0.0 | 边界 |

## 状态机

```
Idle ──check──> Checking ──┬─> NoUpdate          （静默）
                            ├─> OptionalUpdate    （可跳过；跳过记指纹）
                            ├─> ForcedUpdate      （x.y 变化；不可跳过）
                            └─> Unknown           （无法比较；静默）
```

## 错误模型

| 场景 | 判定 | 用户可见行为 |
|---|---|---|
| 版本号不可解析 | Unknown | 无 UI |
| 远端通道（Release API 与 version.json）均失败 | Unknown | 无 UI；下次节流窗口再试 |
| 指纹缺失 | 退化为按版本号比较 | 可选更新 |

## 对照结论

- 双跑差异：B 的既有实现把「指纹不一致」判为**强制更新**；本规格按上表第 3 条判为**可选更新**。
  取舍理由：同版本号重打包属于「重新下载」而非「必须升级」，强制会无谓阻断用户；
  真正必须阻断的是**安装阶段**的签名不一致，那属于安装守卫，不属于更新判定。
- 版本号解析失败一律静默，遵循 B 的防御性哲学（「不编造版本」）。

## 风险与降级

- 指纹来源统一取 Release 附件 `*.sha256` 的摘要；**不采用** `target_commitish` 等与产物无关的字段。
- 降级路径：无法取得指纹时退化为按版本号比较（仅 x.y 变化仍强制）。
