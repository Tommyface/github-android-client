# P13 · 生态对照评审与修改意见（基于 v0.5.2）

> 日期：2026-11-24
> 方法：逐项调研 8 个参考项目的核心机制（官方文档/README/工程博客原文），对照本项目 v0.5.2 现状，输出可执行修改意见。
> 定位约束：本项目是「发现 → 评估 → 下载」工具型客户端，零后端、可离线、零不可控依赖；凡与此冲突的建议列入负面清单。

## 二、P0（低成本高收益，建议 v0.5.3 一批实施）

### M1 · 镜像池 + 自定义代理前缀 + Release 资产代理化

- **参考**：gh-proxy README 明言公共演示站「有点不堪重负，大量使用请自行部署」；本项目当前仅 ghfast.top（全量代理）+ jsdelivr（raw-only）两档硬编码，公共实例一旦失效即退化直连。
- **差距**：①镜像不可配置；②仅 archive URL 参与镜像判定，`releases/download/...` 资产未代理化（恰是 APK 大文件的主体）。
- **意见**：
  1. 内置镜像池常量（≥3 候选），下载失败自动按池轮换（`MirrorLatencyProbeImpl` 已有测速基础）；
  2. 设置页新增「下载加速」：自定义代理前缀（用户可自部署 [gh-proxy CF Worker](https://github.com/hunshcn/gh-proxy) 后填入）；
  3. 镜像判定扩展到 release 资产 URL（`/releases/download/` 模式与 archive 同构，可直接改写）。
- **落点**：`core/data/mirror`、settings、`feature/download`；**风险**：代理方可见下载流量，必须与 M3 的 SHA-256/签名校验联动兜底。

### M2 · octokit API 卫生三件套

- **参考**：GitHub REST 官方惯例——列表响应带 [Link header](https://docs.github.com/en/rest/using-the-rest-api/pagination?apiVersion=2022-11-28) 判断末页；限流响应带 `X-RateLimit-Remaining/Reset`，secondary rate limit 403 带 `Retry-After`。
- **差距**：①分页以「空页」判断结束（多一次无效请求）；②403 仅文案提示，不读取 Retry-After 自动退避；③限流余量无处可看。
- **意见**：①`GitHubApiClient` 统一解析 Link header 供分页层使用；②403 且带 `Retry-After` 时自动单次延迟重试；③权限体检页新增「API 限流余量」卡片（剩余额度 + 重置时间），与三凭证判定并列。
- **落点**：`core/data/GitHubApiClient`、`search`、`permission`。

### M3 · 自更新 APK 签名指纹预校验

- **参考**：Obtainium 在官方页公布[签名证书 SHA-256 指纹](https://github.com/ImranR98/Obtainium)并配 PGP 公钥校验资产哈希；Android 系统只校验更新签名一致，不校验「首次安装来源」。
- **差距**：本项目下载链已校验 Release `digest`（SHA-256），但**未校验 APK 签名指纹**——若镜像/代理返回同哈希不同签名文件（理论上需同时攻破 digest）或 digest 缺失的资产，仍会引导安装。
- **意见**：下载完成后、引导安装前，用 `PackageManager` 读取 APK 签名证书，与内置指纹 `59c63608…cdb8`（v0.1.0 起六版连续不变）比对，不匹配删除文件并告警。
- **落点**：`feature/download` + `release`（与 Sha256Verifier 并列）；**成本**：低（一个校验函数 + 测试）。

### M4 · 版本判定 versionCode 优先

- **参考**：F-Droid index 以 `versionCode` 为权威版本序（[packages API](https://f-droid.org/docs/All_our_APIs/) 返回 `suggestedVersionCode`）；Obtainium 亦以 versionCode 判定升级。
- **差距**：`UpdateChecker` 目前仅按 tag 语义版本比较，tag 不规范（如 `v0.5.2-hotfix`、漏 v 前缀）时可能漏判。
- **意见**：自更新判定改为 `versionCode` 优先（Release 体或索引中携带），semver 作为展示与回退；`SemanticVersion` 保留用于用户可读对比。
- **落点**：`UpdateChecker` / `app`（BuildConfig versionCode 已是单一事实源）。

## 三、P1（结构性升级，建议 v0.6.0 一批）

### M5 · F-Droid 式签名版本索引（自更新安全闭环）

- **参考**：F-Droid [index-v2]：索引文件全量签名 + `entry.json`（时间戳 + 过期）+ diff 增量 + 镜像列表内嵌签名元数据；客户端 ETag 缓存防追踪。
- **意见**：在本项目仓库（或 Pages）放置 `index.json`：`versionCode / versionName / sha256 / changelog / assetMirrorUrls`，外层 entry 元数据带 `timestamp` 与 `maxAge`——**索引过期即拒绝采信**，防止陈旧索引长期冒充最新。第一档先做 sha256 + timestamp（成本极低）；第二档演进 Ed25519 客户端验签（需内置公钥，私钥放 GitHub Secrets）。与 M3/M4 组成完整自更新链：**索引（含镜像列表）→ 下载（镜像池轮换）→ digest 校验 → 签名指纹校验 → versionCode 判定 → 引导安装**。

### M6 · README 渲染（CarGuo 对照项）

- **差距**：仓库详情无 README，评估仓库需跳浏览器。
- **意见**：`GET /repos/{owner}/{repo}/readme`（`Accept: application/vnd.github.raw+json`）取原文；渲染首选 [Markwon](https://github.com/noties/Markwon)（纯 Android 库，无 WebView 强依赖），保守方案用离线 WebView 渲染。**约束**：代码块与图片经 M1 镜像改写，避免 raw.githubusercontent.com 直连超时。

### M7 · 通知中心（CarGuo 对照项）

- **现状**：Device Flow scope 已请求 `notifications`，但 App 内无通知面——scope 白白占用授权提示面积。
- **意见**：新增 notifications 模块：`GET /notifications`（全部/未读过滤）+ 单条与全部标记已读；入口挂 profile 页。**顺带**：P11 权限体检的 notifications 探测端点已存在，可直接复用。

### M8 · 资产筛选与预发布开关（Obtainium 对照项）

- **意见**：①自更新资产按文件名模式（`.apk`、abi 后缀）自动筛选，替代人工指认；②设置页「允许预发布」开关——关闭时取 `/releases/latest`，开启时取最新 release（含 prerelease）并标注。

### M9 · 镜像测速选优 UI（Droid-ify 对照项）

- **意见**：设置页展示镜像延迟榜（`MirrorLatencyProbe` 已在跑）+ 「自动选优」默认开；自定义前缀（M1）与测速结果同屏呈现。

## 四、P2（亮点/长线，按需排期）

### M10 · 星标趋势曲线（star-history 对照项）

- **关键前提**：GitHub 于 2026-06-30 起[限制旧 stargazers 端点](https://www.star-history.com/blog/new-github-star-history-api)为仓库 admin/collaborator，并新增按周聚合端点 `GET /repos/{owner}/{repo}/stargazers/history`（每页 30 周、至多 100 页、无需身份）与 `GET /repos/{owner}/{repo}/stargazers/count`。
- **意见**：仓库详情新增「星标趋势」卡片：拉取 history 端点按周累计，Compose Canvas 自绘折线（零图表依赖）。**实施前必须先 curl 实测该端点对普通 token 的可用性与分页行为**（新端点，行为以实测为准），通过后再编码。

### M11 · Issue/PR 只读浏览（CarGuo 对照项）

- **意见**：先做只读（列表 + 详情 + 评论时间线，Markdown 复用 M6 渲染器）；写操作（评论/关闭）依赖 `repo` scope 已具备，但按「工具客户端」定位后置。

### M12 · 下载断点续传（gh-proxy/Droid-ify 对照项）

- **意见**：下载引擎接入 `Range`/206 分块续传，配合 M1 镜像轮换——切换镜像时从已收字节偏移续传，弱网大资产体验显著改善。

### M13 · GraphQL 详情聚合（CarGuo 对照项，有兼容性前提）

- **意见**：仓库详情用一次 GraphQL 查询聚合 stars/forks/latestRelease/README，替代多次 REST round-trip。**注意**：fine-grained PAT **不支持** GraphQL API，仅 OAuth token / classic PAT 可用——实施前需按登录凭证类型降级（OAuth 走 GraphQL，PAT 走 REST），或直接后置。

## 五、负面清单（明确不做）

| 项 | 理由 |
|---|---|
| Webhook / 服务端 / User-level GitHub App | P12 已论证：8h token 过期与私钥分发风险，现状永久凭证全面占优 |
| Issue 写操作、代码编辑器、CI 触发等全功能扩张 | 偏离「发现-评估-下载」定位（CarGuo 是全功能学习型项目，不宜整体对标） |
| 硬编码更多不可控第三方公共代理 | 代理可见下载流量；新增公共源须逐个可信评估，优先引导自部署 |
| Shizuku/Root 静默安装（Droid-ify 有） | 引入特权依赖面，与零权限膨胀原则冲突 |

## 六、建议实施顺序

1. **v0.5.3（P0）**：M1 → M2 → M3 → M4（一批网络层与自更新安全，均为低风险增量）
2. **v0.6.0（P1）**：M5（索引）→ M8 → M9 → M6 → M7
3. **长线**：M12 → M10（先实测端点）→ M11 → M13（先测凭证兼容）

> 全部条目沿用既有纪律：每批前先列复盘清单确认范围 → 编号实施 → 8 项门禁全绿 → bump 版本号并全仓同步 → MD5/字节数入档。
