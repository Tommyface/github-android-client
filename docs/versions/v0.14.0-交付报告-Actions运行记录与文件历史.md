## 一、前置实测证据（开工前完成）

| 端点 | 结果 | 关键证据 |
|---|---|---|
| `GET /repos/{o}/{r}/actions/runs?per_page=3` | 200 | `{total_count, workflow_runs[]}`；run 项含 id/name/event/status/conclusion/head_branch/head_sha/run_number/html_url/created_at/updated_at |
| `GET /repos/{o}/{r}/commits?path=README.md&per_page=2` | 200 | 返回 commit 数组（`sha`/`commit.message`/`commit.author`），文件级提交历史可用 |
| `GET /repos/{o}/{r}/blame/{path}` | **不存在** | 匿名实测 404；GitHub REST OpenAPI 描述 842 条路径**无 blame**、官方文档页无该端点 |

### 关键结论：A4 前置实测纠正
功能需求清单标注「代码行 Blame 有 REST 端点」**经实测证伪**——GitHub REST 未提供公开 blame 端点（OpenAPI 全量路径与文档双重核验）。按项目「不臆造数据、诚实降级」纪律，**A4 降级为「文件提交历史」**：用真实可用的 `commits?path=` 端点展示某文件逐次提交，UI 明示「非逐行 blame」。这避免了对不存在端点的臆造实现。

## 二、本批交付（对照 ABCD 排期）

### A3 · Actions 运行记录（只读）

- **domain**：`RunStatus` 归一化（completed/in_progress/queued…）+ `WorkflowRun`（shortSha/normalizedStatus/normalizedConclusion）+ `WorkflowRunPage`（runs + hasMore）。
- **data**：`ActionsDtos.kt`（WorkflowRunsResponseDto / WorkflowRunDto + toPage，hasMore 按本页条数判定）；`GitHubRepoApi.listWorkflowRuns`（`/actions/runs?page=&per_page=`）；`RepoRepositoryImpl` 委托；DI 注册 `ListWorkflowRunsUseCase`。
- **presentation**：`ActionsViewModel`（分页加载 + 加载更多 + 失败提示）；`ActionsScreen`（run 卡片：编号/名称/状态/结论/事件/分支@短 SHA，点条目跳浏览器看 run 详情与日志）；详情页新增「⚙ Actions 运行记录」入口 + `Route.Actions` 导航。
- **诚实边界**：只读列表，**不提供**触发/重跑/取消 run（B 类写操作后置）；日志走浏览器查看，不臆造日志 API。

### A4 · 文件提交历史（原 Blame 降级）

- **domain**：复用 `CommitSummary`（v0.12.0），新增 `ListFileCommitsUseCase` + repository 契约 `listFileCommits`。
- **data**：`GitHubRepoApi.listFileCommits`（`commits?path={path}&ref={ref}&per_page=30`，path/ref 走 `encodeURLPath`）；DTO 映射复用 `CommitItemDto.toSummary()`。
- **presentation**：`FileBrowserViewModel` 增 `fileHistory` 状态与 `showFileHistory()`（打开文件时清空、返回目录时清空）；文件视图新增「🕘 文件历史」按钮 + 历史卡片（短 SHA + 标题，上限 20 条），页脚明示「GitHub REST · commits?path=（非逐行 blame）」。
