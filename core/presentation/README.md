# core:presentation · 设计系统与通用组件

> 本模块是**全 App 唯一**的视觉与交互规范归属地。业务 feature 的 `presentation` 层
> 允许依赖本模块；本模块**不得**依赖任何 `feature/*`（konsist 规则 5）。

## 一、职责

| 目录 | 职责 | 状态 |
|---|---|---|
| `theme/` | 色彩、排版、形状、主题模式（浅/深/跟随系统）、动态取色 | 待 UI 里程碑交付 |
| `tokens/` | 间距、圆角、层级、动效时长与缓动、触控尺寸 | 待 UI 里程碑交付 |
| `components/` | 通用组件（状态空/错误视图、危险确认、提交栏、日志视图、Diff 视图等 18 个） | 待 UI 里程碑交付 |
| `markdown/` | Markdown 渲染：核心 `MarkdownLite`（零依赖）+ 可选 `Markwon` 路径 | 待 UI 里程碑交付 |
| `icons/` | Octicons（MIT）→ VectorDrawable 规范化 | 待 UI 里程碑交付 |

## 二、硬约束

1. **单一色源**：组件不得写死色值，一律取自令牌；detekt/lint 自定义规则将拦截裸色值与裸字号。
2. **对比度**：正文 ≥4.5:1，大字/图标 ≥3:1；状态信息必须「颜色 + 文字」双编码（色盲可用）。
3. **触控**：可点击元素 ≥48dp；列表行 ≥56dp。
4. **字号**：支持系统 200% 放大，标题允许换行、按钮文案不截断。
5. **动效**：仅用于状态切换、列表入场、Sheet 展开、加载反馈；禁止无限循环装饰动效与大面积位移；
   必须响应系统关闭动画的降级。
6. **语义**：可点击元素必须有 `contentDescription` 或语义角色；列表需提供 `stateDescription`。

## 三、与 UI 规范的关系

本模块的令牌取值与组件清单以《GHHub 最优修改报告》§6–§11 为准；
实现进度与既有 Frost 视觉体系（分支 `feat/frost-ui`）的合并策略见该报告 §5.1 与 §14.2。

## 四、门禁

- konsist 规则 5：feature 间禁止横向依赖（含反向依赖本模块以外的 feature）。
- konsist 规则 10：Compose 组件不得直接调用网络层。
- 视觉回归：Paparazzi 基线（≥8 屏，Light + Dark）。
