## 二、改动清单

### M5 + M8：更新闭环（app 层）

- `UpdateChecker.kt`
  - `ReleaseAssetDto` 增加 `digest` 字段；`officialSha256()` 解析 `sha256:` 前缀（64 位十六进制校验、小写归一化）
  - `UpdateInfo` 增加 `sha256`、`assetSize`
  - `check(includePrerelease)`：开时改用 `GET /releases?per_page=15`，`pickNewestRelease()` 优先取 body `versionCode:` 最大者，无标记按 published_at 降序
  - `isApkOrZip()` 资产筛选（APK 优先、zip 兜底）
- `UpdateCheckWorker.kt`：读取预发布开关（与手动检查共用 `UpdateCheckPrefs`）；通知文案带 SHA-256 前 16 位；点击直达应用内「检查更新」页（不再跳浏览器）
- 新增 `UpdateCheckViewModel` / `UpdateCheckScreen`（「我的 → ⬆️ 检查更新」）：
  - 当前版本 + versionCode 展示；手动立即检查
  - 新版本卡片：tag、APK 大小（MB）、官方 SHA-256 前 16 位（摘要缺失时提示降级为指纹校验）
  - 「应用内下载」→ `DownloadManager.enqueue(DownloadRequest(expectedSha256=…))` → 下载完成 SHA-256 校验 + APK 签名指纹校验双闸
  - 预发布开关 Switch（持久化，与 Worker 共用）
- `MainActivity`：通知 extra `open_update_check` 直达更新页；`AppNavigation` 支持 startDestination 注入

### M6：README 渲染（repo 三层）

- `GitHubRepoApi.getReadme`（`GET /repos/{owner}/{repo}/readme`，base64 解码）
- `ReadmeDto.toDomain()`：base64（Mime）解码 + 编码校验；`Readme` 领域模型
- `RepoRepository.getReadme`：**404 与解码失败均以 `Success(null)` 表达**（无 README 是常态而非错误）
- `GetReadmeUseCase` + DI 注册（data/presentation 两处）
- `RepoViewModel`：`ReadmeUiState`（Idle/Loading/NotAvailable/Loaded），`openDetail` 成功后自动加载；失败静默不打扰主流程
- `RepoDetailScreen`：整体重构为**单一 LazyColumn**（沿用 v0.5.1 修复 Release 详情的已验证模式，杜绝 Column 嵌套滚动截断）
- 新增 `MarkdownLite.kt`（轻量解析器，宁降级不丢内容）：
  - 块级：1–6 级标题、段落、无序/有序列表、围栏代码块、独立图片行、分隔线
  - 行内：`**粗体**`、`` `code` `` 等宽底色、`[链接](url)` 降级为「文字 (url)」
  - HTML 标签/实体剥离 + 连续空格压缩
  - `rewriteReadmeImageUrl()`：raw.githubusercontent.com / github.com/*/raw → fastly.jsdelivr.net/gh/{owner}/{repo}@{ref}/{path}；相对路径锚定默认分支；他仓外链原样保留
  - 图片渲染走 Coil（`AsyncImage`）

### M7：通知中心（profile 三层）

- `GitHubNotification` / `NotificationSubject` 领域模型
- `NotificationDto`（id 十进制字符串 → threadId Long 转换）
- `GitHubUserApi.listNotifications`（`GET /notifications?per_page=50`）/ `markThreadRead`（`PATCH /notifications/threads/{id}`）
- `ProfileRepository` 接口与实现、`ListNotificationsUseCase` / `MarkNotificationReadUseCase`、DI 注册
- `NotificationsViewModel`：未读列表、本地乐观标记已读、错误文案区分（401 → 登录失效；404 → 无 Notifications 读权限，引导权限体检）
- `NotificationsScreen`：未读数标题、未读圆点高亮、点击标记已读 + 打开主题 URL
- 「我的 → 🔔 通知中心」入口 + 路由注册

### M9：镜像测速 UI（download/presentation）

- `sortMirrorsByLatency()`：已测速按延迟升序，未测速保持原相对顺序排后（纯函数可单测）
- `MirrorSettingsScreen`：测速后自动排序展示；最快镜像 🏆 标记；「超时」（测速过但缺席）与「未测速」状态区分

## 六、风险与已知边界

- 通知点击打开的是 subject API URL（GitHub 服务端会重定向到网页端），非 html_url——保持零额外请求的取值成本
- README 链接降级为「文字 (url)」纯展示，不做应用内跳转（避免 ClickableText 兼容面）
- `konsist-test` 架构约束沿用现有规则；M5/M8 的 ViewModel 落位 app 层（更新属于应用自身职责，不属任何 feature）
