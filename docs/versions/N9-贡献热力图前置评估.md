# N9 · 贡献热力图前置评估（v0.12.0）

> 日期：2026-11-25
> 结论：**no-go，维持降级为「跳网页查看」**。依据为 GitHub 官方文档 + M13 既有证据 + 本环境无有效 token 实测；按 P14 排期约定「绑定 M13 前置条件，否则降级为跳网页查看」执行。

---

## 一、评估目标

P14 排期对 N9（贡献热力图）的前置要求：

> 先解 M13 前置：auth.domain 暴露 AuthMethod + GitHubApiClient 加 GraphQL POST + classic/OAuth token 走 GraphQL、fine-grained PAT 降级隐藏。

即要在本项目凭证体系下让 `contributionsCollection` 可用，并让 fine-grained PAT 用户有明确降级行为。

---

## 二、实测/查证证据（2026-11-25 复核，非凭旧证据）

| 证据 | 来源 | 内容 |
|---|---|---|
| GitHub 官方文档（GraphQL 鉴权） | [Forming calls with GraphQL](https://docs.github.com/enterprise-server@3.3/graphql/guides/forming-calls-with-graphql) | 原文：**"The GraphQL API does not support authentication with fine-grained personal access tokens."** GraphQL 仅支持 classic PAT / OAuth token / GitHub App |
| GraphQL 字段实测（第三方公开记录，2026-09-18） | [gitstats PRIVATE-ACTIVITY](https://github.com/yaroslavhaidash/gitstats/blob/main/docs/PRIVATE-ACTIVITY.md) | fine-grained PAT（Contents: read）查 `contributionsCollection`：私有仓库不列出，只拿到 `restrictedContributionsCount` 一个数字；classic PAT（repo scope）能拿完整日历 |
| 同类问题旁证（2026-09-22） | [zaccesss issue #64](https://github.com/zaccesss/zaccesss/issues/64) | "Fine-grained tokens cannot get this data at all currently, regardless of scope." |
| 官方 token 能力边界 | [Managing your personal access tokens](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens) | fine-grained PAT 存在能力缺口且 GitHub 标注会逐步补齐，但未承诺 GraphQL 支持时间表 |
| 本环境凭证 | `env` 无 GH_TOKEN/GITHUB_TOKEN/PAT；M13 实测有效 token 缺失 | 无法实测「classic/OAuth 走 GraphQL 成功 + fine-grained PAT 被拒」真实行为，最关键决定项不可验证 |

结论：**核心障碍是平台能力边界（fine-grained PAT 不支持 GraphQL），不是本项目代码问题**；且无有效 token 无法完成兼容性实测。

---

## 三、架构成本复核（代码定位）

| 事实 | 位置 |
|---|---|
| `AuthSession.method: AuthMethod?`（OAUTH/PAT）存在于 auth.domain | `feature/auth/domain/.../model/AuthModels.kt:20-23,42` |
| `AuthTokenProvider` 只暴露 `tokenFor(channel)`，不暴露凭证类型 | `core/domain/.../network/ApiModels.kt` |
| `repo:data` 不依赖 auth.domain，无法读取 AuthMethod | `feature/repo/data/build.gradle.kts` |
| `GitHubApiClient` 无 GraphQL POST 通道 | `core/data/.../network/GitHubApiClient.kt` |

要解 N9 需同时改造：core.domain 凭证类型抽象 + core.data GraphQL 通道 + repo.data 凭证分流 + 测试替身。属跨模块中高成本改造，且即使完成，**fine-grained PAT 用户仍只能看到降级**——本项目主力凭证正是 PAT（P11 权限体检围绕 PAT 设计）。

---

## 四、决策

- **不实现** GraphQL 贡献热力图；不臆造贡献数字、不引入第三方聚合。
- **降级方案**：个人主页提供「贡献热力图 → 在网页查看」入口，点击用系统浏览器打开 `https://github.com/{login}`，UI 明示原因（热力图仅 GraphQL 提供，fine-grained PAT 不支持）。
- 前置若未来满足（有效 classic/OAuth + fine-grained PAT 各一枚可实测，且凭证类型贯穿方案落地），按 P14 重启评估。

---

## 五、负面清单对齐

与 P13/P14 一致：不引入不可控依赖、不突破「发现-评估-下载」定位、不为单屏视觉元素做高成本跨模块改造。跳网页是诚实降级，优于臆造数据。
